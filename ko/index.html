eax: Wycheproof 시험 벡터 추가 RustCrypto/AEADs #894 · 시험 보강
문제
eax 크레이트의 실패 벡터 파일이 비어 있어, 틀린 태그를 거부하는지 보는 시험이 없었습니다. 태그 비교를 항상 통과로 바꿔도 모든 시험이 통과했고, AES-192·AES-256은 시험 벡터가 하나도 없었습니다.
배경 지식
암호모듈 검증(KCMVP)의 기지 답 시험과 같은 방식으로, 공개 시험 벡터(Wycheproof)를 돌리고 위조한 태그를 거부하는지 확인했습니다.
찾은 방법
Wycheproof AES-CCM·AES-EAX 벡터 전부(672개, 불일치 0)를 크레이트에 돌린 뒤 크레이트 시험이 무엇을 덮는지 봤습니다. 태그 검사를 끈 변이가 기존 시험을 통과했습니다.
수정
AES-128·192·256 Wycheproof 186개(유효 105·무효 81)를 aead 시험 매크로로 넣었습니다. 태그 검사를 끄면 새 실패 시험 3개가 실패합니다.

문제
rsa 크레이트의 Wycheproof 시험은 PKCS#1 v1.5·PSS 서명만 돌렸습니다. OAEP 패딩 검사 세 가지(첫 바이트 0, 구분자 0x01 앞의 0 아닌 바이트, 구분자 없음) 중 하나를 빼도 시험이 모두 통과했습니다.
배경 지식

찾은 방법
변이 시험으로 찾았습니다. 패딩 검사를 하나씩 빼고 기존 시험을 돌린 뒤, 같은 변경을 Wycheproof OAEP 벡터로 다시 돌렸습니다.
수정
새 시험 test_rsa_oaep_decrypt가 22개 파일의 벡터 1,098개를 돌립니다. 세 변이 모두 그중 21개 파일에서 실패합니다.

p11-kit은 자체 RPC 형식으로 프로세스 사이에 PKCS#11 호출을 주고받기 때문에, 응답 디코더가 읽어 들이는 모든 길이를 경계 검사해야 합니다. PKCS#11·HSM 경험을 썼습니다.
찾은 방법
RPC 응답 디코딩 경로를 읽고 p11-kit 비공개 보안 경로로 보고했습니다.
수정
메인테이너는 보안 문제가 아닌 버그로 분류하고(SECURITY.md상 RPC 클라이언트와 서버는 한 신뢰 경계 안) 중첩 속성 길이를 경계 검사하는 수정을 공개 PR #797로 2026-11-06 머지했습니다. Hansaem Wi가 보고자이자 공동 작성자로 올라갔습니다.
