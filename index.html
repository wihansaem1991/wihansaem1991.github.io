OpenSSL — Clear the PBKDF1 derived key in kdf_pbkdf1_derive_skey()Approved

openssl/openssl #33444 · submitted 2026-10-29 · Approved 2026-10-30 · master, 3.6, 4.0, 4.1
Problem
The derived key was imported as an EVP_SKEY and its temporary buffer freed with OPENSSL_free(), leaving the whole key in released heap memory.
Background
Key zeroisation as required by ISO/IEC 19790, the standard behind FIPS 140-3 and Korea's KCMVP validation: a derived key is secret material and has to be cleared before its memory is released. OpenSSL provides OPENSSL_clear_free() for exactly this.
How it was found
A measurement program that replaces OpenSSL's allocator and scans every freed block for key bytes: a 20-byte block holding the full key, freed at pbkdf1.c:318.
Fix
OPENSSL_clear_free() on both paths; test_kdf_pbkdf1_skey now watches freed blocks and fails if the change is reverted.
Review
Approved by two reviewers; triaged as a bug with FIPS relevance.
